## 1. ระบบตรวจด้วยภาพในโรงงานมีอะไรบ้าง

```
ชิ้นงาน → handling (สายพาน/หุ่นยนต์ จัดตำแหน่ง)
       → lighting + optics + camera  (ถ่ายภาพ)
       → preprocessing               (crop, normalize)
       → model                       (ให้ score หรือ mask)
       → decision rule               (score ≥ threshold → reject)
       → action                      (ผ่าน / คัดออก / ส่งคนตรวจซ้ำ)
       → logging                     (เก็บภาพ + ผล → ใช้ retrain)
```

ข้อสังเกตสามข้อที่คนทำ AI มักลืม

1. **โมเดลเป็นแค่กล่องเดียว** ถ้าแสงไม่ทำให้ตำหนิ "เห็น" ในภาพ โมเดลก็หาไม่เจอ ปัญหาจำนวนมากในหน้างานแก้ที่แสงหรือมุมกล้อง ไม่ใช่ที่โมเดล
   ในสัมภาษณ์ ถ้าคุณพูดถึงเรื่องนี้เอง จะดูเป็นคนที่เข้าใจหน้างาน
2. **Decision rule แยกจากโมเดล** โมเดลให้ตัวเลข แต่การตัดสินว่า "เสีย" เป็นนโยบาย (threshold, พื้นที่ขั้นต่ำ) ที่ต้องตกลงกับฝ่าย Quality
3. **Logging คือจุดเริ่มของ feedback loop** (Day 14) ภาพที่ถูกตีกลับหรือที่คนตรวจซ้ำแล้วเห็นต่าง คือข้อมูลที่มีค่าที่สุดสำหรับการเทรนรอบถัดไป

**Rule-based AOI vs deep learning:** ระบบเดิมใช้กฎ เช่น threshold ความสว่าง, blob analysis, template matching
ซึ่งดีเมื่อชิ้นงานสม่ำเสมอและตำหนิชัด deep learning เหมาะเมื่อพื้นผิวมีลายหรือความแปรปรวนสูง (เช่น โลหะขัดเงา ที่แสงสะท้อนเปลี่ยนตามมุม)
และตำหนิมีหลายรูปแบบจนเขียนกฎไม่ไหว ราคาที่ต้องจ่ายคือต้องมีข้อมูลและ label ที่ดี

## 2. Positive class และ confusion matrix ในภาษาโรงงาน

ในงานตรวจตำหนิ ให้ **positive = ชิ้นเสีย (NG)** เสมอ แล้วเขียนนิยามนี้ไว้ในเอกสาร เพราะทุกตัวเลขขึ้นกับมัน

|                     | จริง: NG (เสีย) | จริง: OK (ดี) |
|---|---|---|
| **ระบบ: reject**    | TP              | FP → **False Reject** (overkill) |
| **ระบบ: accept**    | FN → **False Accept** (escape, underkill) | TN |

นิยามอัตรา (แบบที่ใช้ในคอร์สนี้)

- **FR rate** = FP / (FP + TN) — ในบรรดา **ชิ้นดีทั้งหมด** ถูกตีกลับกี่ %
- **FA rate** = FN / (FN + TP) — ในบรรดา **ชิ้นเสียทั้งหมด** หลุดไปกี่ % (= 1 − recall)

> ⚠️ **ต้องถามนิยามทุกครั้ง** บางโรงงานคิด FA เทียบกับ "ชิ้นงานที่ผลิตทั้งหมด" ไม่ใช่เทียบกับชิ้นเสีย
> ถ้า defect rate 1% ตัวเลขสองแบบนี้ต่างกัน 100 เท่า การถามเรื่องนี้ในวันแรกของงานคือสัญญาณว่าคุณเป็นมืออาชีพ

**เชื่อมกับประสบการณ์ของคุณ:** ใน biometrics (งาน iris ที่ NECTEC) ก็มี FAR/FRR เหมือนกัน
แต่ positive ที่นั่นคือ "เป็นคนเดียวกัน" การตั้ง threshold ของ Hamming distance คือการเลือก operating point แบบเดียวกับที่เราจะทำในงานนี้
คุณเล่าเรื่องนี้เชื่อมกันในสัมภาษณ์ได้

### ตัวอย่างตัวเลข: ทำไม accuracy ใช้ไม่ได้

ผลิต 10,000 ชิ้น defect rate 1% → เสีย 100, ดี 9,900
โมเดลจับชิ้นเสียได้ 98% และตีกลับชิ้นดี 3%

|  | จริง NG | จริง OK |
|---|---|---|
| reject | TP = 98 | FP = 297 |
| accept | FN = 2 | TN = 9,603 |

- FA = 2/100 = **2%**, FR = 297/9,900 = **3%**
- Accuracy = (98 + 9,603) / 10,000 = **97.0%**
- Precision = 98 / (98 + 297) = **24.8%** — ชิ้นที่ถูกตีกลับ 3 ใน 4 เป็นชิ้นดี

ทีนี้ลองโมเดลที่ "ปล่อยผ่านทุกชิ้น" accuracy = 9,900/10,000 = **99%** สูงกว่าโมเดลแรก แต่ FA = 100%
**บทเรียน:** ในข้อมูลไม่สมดุล accuracy หลอกได้เสมอ ใน resume และสัมภาษณ์ ให้พูดเป็น FR/FA หรือ recall ที่ FR คงที่

สังเกตด้วยว่า precision ต่ำ (24.8%) ไม่ได้แปลว่าระบบแย่ ถ้ามีคนตรวจซ้ำชิ้นที่ถูกตีกลับ ฝ่ายผลิตอาจยอมรับได้ ขึ้นกับต้นทุน ซึ่งพาไปหัวข้อถัดไป

## 3. Cost asymmetry และ operating point

โมเดลส่วนใหญ่ให้ **score** s ∈ [0, 1] แล้วเราตัดสินด้วย threshold t: ถ้า s ≥ t ให้ reject

- เพิ่ม t → reject น้อยลง → FR ลด แต่ FA เพิ่ม
- ลด t → reject มากขึ้น → FA ลด แต่ FR เพิ่ม

FR กับ FA จึงแลกกันเสมอ จุด (FR, FA) ที่เราเลือกใช้เรียกว่า **operating point**
โมเดลที่ดีกว่าคือโมเดลที่ทั้งเส้นโค้ง FR–FA อยู่ต่ำกว่า ไม่ใช่โมเดลที่ได้ตัวเลขดีที่ threshold 0.5

### เลือกจุดด้วยต้นทุน

ต้นทุนรวม: **C = c_FA · FN + c_FR · FP**

สมมติชิ้นเสียหลุดถึงลูกค้ามีต้นทุน 500 บาท (เคลมคืน, เสียชื่อ) และตีกลับชิ้นดีมีต้นทุน 5 บาท (ค่าแรงตรวจซ้ำ) อัตราส่วน 100 : 1

| threshold | FN | FP | ต้นทุน |
|---|---|---|---|
| หลวม | 5 | 100 | 2,500 + 500 = 3,000 |
| กลาง | 2 | 297 | 1,000 + 1,485 = **2,485** |
| เข้ม | 1 | 600 | 500 + 3,000 = 3,500 |

จุดกลางถูกที่สุด แม้จะตีกลับชิ้นดีเกือบ 300 ชิ้น

### เลือกจุดด้วยข้อจำกัด (constraint-first)

ในทางปฏิบัติ ต้นทุนประเมินยาก และลูกค้ามักให้ spec มาเป็นข้อจำกัด เช่น "FA ≤ 0.5%"
นโยบายที่ใช้บ่อยที่สุดคือ **ล็อก FA ไม่ให้เกินเป้า แล้วเลือก threshold ที่ทำให้ FR ต่ำที่สุด**
และต้องเลือกบน **validation set** เท่านั้น ห้ามใช้ test set (เหตุผลจะลงลึกใน Day 4 และ Day 11)

## 4. Rare event: test set ของคุณพิสูจน์อะไรได้แค่ไหน

นี่คือจุดที่พื้น probability ของคุณได้ใช้จริง

สมมติระบบมี FA rate จริงเท่ากับ p และเราทดสอบกับชิ้นเสีย n ชิ้น ความน่าจะเป็นที่จะ **ไม่หลุดเลยสักชิ้น** คือ

P(0 escapes) = (1 − p)ⁿ

ถ้าเราเห็นว่าหลุด 0 ชิ้น แล้วอยากบอกด้วยความมั่นใจ 95% ว่า p ไม่เกินเท่าไร ให้แก้ (1 − p)ⁿ = 0.05

n · ln(1 − p) = ln 0.05 ≈ −3.00  →  เมื่อ p เล็ก ln(1 − p) ≈ −p  →  **p ≈ 3 / n**

เรียกว่า **rule of three**: ถ้าไม่พบความผิดพลาดเลยใน n ครั้ง ขอบบน 95% ของอัตราความผิดพลาดประมาณ 3/n

### ใช้กับ KolektorSDD2

- test set มีภาพเสีย 110 ภาพ ต่อให้โมเดลจับได้ครบ 110/110 ก็บอกได้แค่ว่า FA ≤ 3/110 ≈ **2.7%** (ที่ 95%)
- requirement จำลองต้องการ FA ≤ 1/200 = **0.5%** ต้องมีภาพเสียอย่างน้อย 3/0.005 ≈ **600 ภาพ** และหลุด 0 ภาพ

ฝั่ง FR ง่ายกว่ามาก เพราะ test มีภาพดี 894 ภาพ วัด FR ระดับ 5% ได้แม่นพอสมควร

**บทเรียน:** การแปล requirement ไม่ได้หมายถึงการตั้งค่าโมเดลอย่างเดียว แต่รวมถึงการบอกลูกค้าว่า
"ด้วยข้อมูลที่มีตอนนี้ ยืนยันได้ถึงระดับไหน และต้องเก็บชิ้นเสียเพิ่มอีกเท่าไร" — นี่คือเนื้อหาของ `problem_spec.md` วันนี้
เมื่อมีความผิดพลาดมากกว่า 0 จะใช้ Clopper–Pearson interval ซึ่งเราจะเรียนใน Day 11

## 5. ตัดสินระดับไหน: ภาพ, วัตถุ หรือ pixel

ไลน์ผลิตตัดสิน **ต่อชิ้น** (image-level: ผ่าน/ไม่ผ่าน) แต่โมเดลอาจให้ผลต่างระดับ

- **Classification** → score ต่อภาพ ใช้ได้ตรง ๆ
- **Detection** → กล่องหลายกล่อง → ต้องมีกฎ เช่น "มีกล่องใดที่ confidence ≥ t"
- **Segmentation** → mask ระดับ pixel → ต้องมีกฎ เช่น "pixel ที่ prob ≥ t รวมกันเกิน A pixel"

กฎ aggregation เป็นส่วนหนึ่งของ decision rule และเป็นที่ที่ requirement ข้อ "รอยเล็กมากไม่นับ" เข้ามา
คุณต้องแปลงคำว่า "มองไม่เห็นด้วยตา" ให้เป็นตัวเลข (เช่น พื้นที่หรือความยาวขั้นต่ำเป็น pixel หรือ mm)
ซึ่งทำได้ก็ต่อเมื่อรู้ความละเอียดของกล้อง (mm ต่อ pixel) — นี่คือคำถามที่ต้องถามลูกค้ากลับ

## 7. กับดักที่เจอบ่อย

1. **รายงาน accuracy** ในข้อมูลไม่สมดุล
2. **เลือก threshold บน test set** แล้วรายงานผลบน test ชุดเดิม → ตัวเลขดีเกินจริง
3. **ไม่ถามนิยาม FR/FA** และตัวหาร
4. **สัญญา spec ที่ test set พิสูจน์ไม่ได้** (ลืม rule of three)
5. **คิดว่าโมเดลแก้ได้ทุกอย่าง** ทั้งที่ปัญหาอยู่ที่แสงหรือ label
6. **ใช้ threshold 0.5 เป็นค่าเริ่มต้น** โดยไม่ดู score distribution

## 8. คำถามที่ interviewer อาจถาม

คิดคำตอบเองก่อน เราจะคุยกันใน explain-back และ mock interview

1. ถ้าลูกค้าบอกว่า "ห้ามหลุดเลย" คุณจะตอบเขาอย่างไร
2. โมเดลได้ accuracy 99% ทำไมยังไม่พอ
3. FR สูงเกินไปจนฝ่ายผลิตบ่น แต่ FA ต้องคงที่ คุณมีทางเลือกอะไรบ้าง (ไม่ใช่แค่ขยับ threshold)
4. คุณจะเลือก threshold อย่างไร และใช้ข้อมูลชุดไหน
5. Test set ของคุณมีชิ้นเสีย 110 ชิ้น คุณยืนยันกับลูกค้าได้ว่า FA ต่ำแค่ไหน
